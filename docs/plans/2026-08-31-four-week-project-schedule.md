# ACG 番剧人物识别桌面系统四周实施计划

> **执行说明：** 本计划按 4 个自然周、18 个实际工作日编排。前三周各 5 天，第四周安排 3 个验收工作日；剩余 2 天作为学校安排、训练等待或严重缺陷缓冲，不主动加入新功能。

**目标：** 在 18 个工作日内交付一个可离线运行的单机桌面系统：导入番剧截图，使用 YOLO 完成人物检测和人物分类，映射番剧，展示 Top-3、人物框和置信度，并保存本地识别历史。

**架构：** PySide6 桌面端负责文件选择、图片预览、结果展示与历史管理；本地 FastAPI 服务负责任务编排、模型推理和输入校验；SQLite 保存番剧、人物、模型版本与识别历史。训练工程继续使用现有 `training/`，桌面系统只加载审核通过的离线模型包。

**技术栈：** Python 3.11、PySide6、FastAPI、SQLite、SQLAlchemy、Ultralytics YOLO、PyTorch/ONNX Runtime、pytest、PyInstaller。

**依据：** `docs/基于YOLO的动漫番剧截图识别与管理系统-项目需求规格说明书-V1.0.docx`、`docs/基于YOLO的动漫番剧截图识别与管理系统-系统设计说明书-V1.0.docx`、`docs/plans/2026-08-31-yolo-training-implementation.md`。

## 范围约束

- 18 天课程版本以“可演示、可测试、可解释”为优先，不承诺识别全网番剧。
- 必做范围：单张截图导入、人物检测、人物 Top-3、番剧聚合、unknown、历史记录、模型信息、异常提示、离线打包。
- 课程可行目标：3–5 部番剧、15–25 名人物；每类尽量 150 张以上。若 AOT 是唯一及时获得且许可明确的数据，则先交付 10–14 人物的单番剧试点，并在报告中明确边界。
- “10 部番剧、50 人物”的正式目标是扩展验收，只有在第 3 天前已经获得完成映射的数据时才继续，否则不得牺牲桌面系统和测试质量强行追赶。
- 不做登录、云端部署、视频实时识别、爬虫、在线模型更新和复杂权限管理。
- 每天结束必须留下可检查的文件、指标或演示结果；训练运行时间不等同于有效工作量。

## 需要学生本人先完成的事项

1. 确认老师接受“受控类别集合”，并确认人物识别是项目亮点而不是必须覆盖全网。
2. 从原始数据页面自行下载数据，阅读并保存许可或课程用途说明；不得把原图上传到代码仓库。
3. 确认最终演示的番剧和人物中文名；人物簇到姓名的映射必须人工复核。
4. 准备独立于训练集的演示截图和测试截图，防止只展示训练数据。
5. 提前确认验收电脑、Python/CUDA 环境、是否允许携带模型权重，以及答辩时间限制。

## 第 1 周：真实数据与可用模型（第 1–5 天）

### 第 1 天：冻结课程范围并取得数据

- 与老师确认最小范围、验收指标和是否必须识别人名。
- 下载 AOT Characters；若已有可合法使用的其他番剧截图，同步建立候选清单。
- 保存数据页地址、版本、许可说明和下载日期。
- 将原始数据放入 `data/raw/`，确认 `.gitignore` 不会提交原始媒体。
- 运行 20–30 张图片的解码检查，确认目录名确实对应人物名。

**当日产出：** `docs/data-source-register.md`、真实数据目录、课程范围确认记录。

**完成标准：** 至少一个许可和标签可确认的数据源可用；不能确认许可的数据不得进入训练。

### 第 2 天：数据清洗与人物映射

- 统计人物类别、每类图片数量、尺寸、损坏图和重复图。
- 统一人物中文名、英文名、别名、`character_id` 和 `anime_id`。
- 每类固定种子抽查 30 张，记录误标、无法辨认、同人图和非截图样本。
- 删除或隔离损坏图、明显误标和许可不明样本。
- 若使用 BangumiBase，生成审核 CSV，填写候选人名并开始双人复核。

**当日产出：** 数据统计表、`character_map.json`、`character_anime_map.json`、抽查记录。

**完成标准：** 每个训练类别有稳定且不重复的人物 ID，抽查误标率不高于 5%。

### 第 3 天：生成训练清单并通过数据门禁

- 使用 `anime-yolo prepare` 生成统一 manifest。
- 执行 SHA256/pHash 去重和 `70/15/15` 分组切分。
- 检查同一来源组、重复图和近重复簇没有跨集合。
- 单独建立 unknown 验证集，包含范围外人物、真人、纯场景和误检测框。
- 冻结测试集文件清单；之后不得使用测试集选择模型或阈值。

**当日产出：** `manifest.csv`、`dataset_audit.json`、冻结测试清单及清单哈希。

**完成标准：** `anime-yolo audit --strict` 通过；每类 train/val/test 都有样本。

### 第 4 天：训练人物分类试点

- 先用 3 类、2 轮配置复核真实数据路径和类别映射。
- 使用 `pilot-aot.yaml` 运行 30 轮人物分类训练。
- 观察训练/验证损失、类别混淆、显存和实际 batch；保留 `best.pt` 与 `last.pt`。
- 完成一次人为中断后的 `last.pt` 续训验证。
- 导出 ONNX 并检查 PyTorch/ONNX 输出误差。

**当日产出：** 分类模型权重、ONNX、训练曲线、实际配置和环境记录。

**完成标准：** 训练正常结束、断点续训有效、ONNX 与 PyTorch Top-1 一致。

### 第 5 天：检测、unknown 与端到端模型冻结

- 在至少 100 张课程测试图上评估现有检测器；重点检查多人、侧脸和遮挡。
- 只有检测召回明显不足时才补标并微调检测器。
- 使用验证集校准最大概率和 Top-1/Top-2 margin 阈值。
- 运行端到端截图推理，检查无人、单人、多人和 unknown。
- 打包课程候选模型，填写模型卡并明确真实指标和限制。

**当日产出：** 检测评估、unknown 阈值、端到端指标、课程候选模型包。

**完成标准：** 任意一张测试截图均能返回合法 JSON；无人图不硬猜人物；模型包可通过完整性检查。

## 第 2 周：本地服务与数据库（第 6–10 天）

### 第 6 天：建立桌面项目骨架

- 创建 `app/`，划分 `desktop/`、`api/`、`domain/`、`inference/`、`database/` 和 `tests/`。
- 固定 PySide6、FastAPI、SQLAlchemy、Pydantic 和打包依赖。
- 建立统一配置、日志、应用数据目录和模型包目录。
- 完成空窗口、本地服务健康检查和 SQLite 连接测试。

**当日产出：** 可启动的桌面空壳、本地 `/health`、测试数据库。

**完成标准：** 一条命令启动应用，窗口和服务均正常退出，不残留后台进程。

### 第 7 天：实现数据库和数据访问层

- 建立 `anime`、`character`、`character_anime`、`model_version`、`recognition_task`、`detection_result` 表。
- 实现数据库初始化、版本迁移和事务封装。
- 实现新增识别记录、查询详情、分页列表和删除记录。
- 测试外键、多人物结果、unknown、重复任务和数据库损坏提示。

**当日产出：** SQLite schema、repository 层和数据库测试。

**完成标准：** 数据库测试全部通过；删除历史不会删除原始用户截图。

### 第 8 天：接入模型推理服务

- 将现有 `YoloScreenshotPredictor` 封装为单例模型服务。
- 启动时验证模型包哈希、映射版本、阈值和必要文件。
- 实现图片类型、大小、分辨率和解码检查。
- 将推理放入工作线程，避免阻塞 UI；捕获 CUDA 不可用和显存不足错误。
- 将结果与模型版本保存到 SQLite。

**当日产出：** 可被 API 调用的推理服务及异常路径测试。

**完成标准：** 同一截图可稳定返回模型版本、人物框、人物候选、番剧候选和耗时。

### 第 9 天：实现本地 API

- 实现 `/health`、`/models/current`、`/recognitions`、`/recognitions/{id}` 和删除接口。
- 明确上传限制、错误码和 Pydantic 响应模型。
- 防止任意文件路径读取，只接受上传内容或应用内部任务 ID。
- 添加 OpenAPI 示例和请求日志，但不记录原图内容。

**当日产出：** 本地 API、接口测试和 OpenAPI 契约。

**完成标准：** 正常、坏图、超限、模型缺失、无人和推理失败路径都有稳定响应。

### 第 10 天：后端集成测试与性能基线

- 从 API 上传截图，验证推理、数据库写入、历史查询的完整链路。
- 连续推理至少 30 张图，记录冷启动、单人、多人 P50/P95。
- 检查模型只加载一次、任务串行控制和内存/GPU 显存释放。
- 修复第 2 周所有阻断缺陷，并冻结 API 字段。

**当日产出：** 后端集成测试报告、性能基线和冻结 API 契约。

**完成标准：** 后端自动化测试全部通过，无重复加载模型和数据库锁死问题。

## 第 3 周：桌面界面、联调与打包（第 11–15 天）

### 第 11 天：主界面与图片导入

- 实现导航、图片选择、拖放、最近文件和清空操作。
- 展示原图、文件信息、加载状态和输入错误。
- 使用后台任务调用本地 API，禁止 UI 主线程执行推理。
- 为大图预览做等比缩放，不修改传给模型的原图。

**当日产出：** 可选图并发起识别的主界面。

**完成标准：** PNG/JPEG/WebP 正常；坏图和超限图有中文提示；推理时窗口仍可操作。

### 第 12 天：人物框与识别结果展示

- 在预览图上按缩放比例绘制人物框和姓名。
- 展示截图级 Top-3 番剧、每个人物 Top-3、置信度和 unknown。
- 实现无人、部分 unknown、多人不同番剧候选等状态。
- 增加模型版本、推理耗时和限制说明。

**当日产出：** 完整识别结果页和四类状态截图。

**完成标准：** 框坐标与原图一致；结果与 API JSON 一致；低置信度不显示为确定姓名。

### 第 13 天：历史记录管理

- 实现历史列表、分页、番剧/人物关键字过滤和日期排序。
- 实现详情页，复现当时模型版本、框、置信度和候选结果。
- 实现单条删除和清空历史二次确认。
- 明确截图保存策略；默认只保存缩略图或文件摘要时，在界面中说明。

**当日产出：** 可查询、查看和删除的历史模块。

**完成标准：** 关闭重启后历史仍存在；删除、空库和数据库异常行为可控。

### 第 14 天：设置、模型信息与可用性完善

- 实现当前模型信息、类别数、模型版本、设备和阈值只读页面。
- 增加日志目录打开、数据库备份和结果 JSON 导出。
- 补齐键盘操作、加载反馈、按钮禁用状态和中文错误提示。
- 检查 1366×768 和常见高 DPI 显示。

**当日产出：** 设置/关于页、结果导出和数据库备份。

**完成标准：** 不依赖开发终端即可理解当前模型能力和失败原因。

### 第 15 天：完整联调与 Windows 打包

- 使用 PyInstaller 生成 Windows 可执行程序或可运行目录。
- 确认模型、映射、阈值、SQLite 初始化脚本和 Qt 插件均被包含。
- 在新目录执行安装/首次启动/识别/历史/退出全流程。
- 运行全量测试并修复所有 P0/P1 缺陷；冻结功能，不再新增页面。

**当日产出：** 课程候选安装包、版本号、全量测试结果。

**完成标准：** 不进入源码目录也能启动；无开发环境路径依赖；基础流程可连续演示三次。

## 第 4 周：验收与答辩（第 16–18 天）

### 第 16 天：验收测试和缺陷清零

- 按需求规格逐条执行功能、异常、数据库和模型验收用例。
- 使用完全独立的截图记录真实准确率，不挑图只展示成功案例。
- 记录 GPU/CPU 环境、冷启动时间和连续推理 P50/P95。
- 修复所有阻断演示的 P0/P1 缺陷；P2/P3 写入已知问题。

**当日产出：** 验收测试报告、缺陷清单、性能与准确率表。

**完成标准：** P0/P1 为零，所有未达指标均在报告中明确解释。

### 第 17 天：整理提交材料与演示脚本

- 更新需求规格、系统设计、数据库设计、接口说明和模型卡，使其与程序一致。
- 准备源码、依赖锁、模型包、可执行程序、测试报告和数据许可清单。
- 制作 6–8 分钟演示脚本：问题背景 → 架构 → 单人 → 多人 → unknown → 历史 → 测试结果。
- 准备 5 张固定演示图和 2 张备用图，确保不是训练样本。

**当日产出：** 最终提交目录、答辩 PPT/讲稿、演示素材清单。

**完成标准：** 文档中的字段、截图、版本号和程序实际行为完全一致。

### 第 18 天：全流程彩排、封版和验收

- 在验收环境完整安装并彩排至少两次，记录总时长。
- 演练模型缺失、坏图、无人图和 CUDA 不可用时的解释与恢复。
- 生成最终文件哈希和提交清单，备份到两个独立位置。
- 封版后只修复阻断问题，不再训练新模型或调整阈值。
- 完成现场验收并记录老师反馈。

**当日产出：** 最终封版、提交清单、备份和验收记录。

**完成标准：** 同一封版在验收机重复运行成功；现场使用的模型、数据库和文档版本可追溯。

## 第 19–20 天缓冲规则（如学校实际提供）

- 仅用于训练意外中断、验收机兼容、打包缺文件和 P0/P1 缺陷。
- 不用于增加登录、视频识别、云端部署或更多番剧类别。
- 若第 18 天已经封版，缓冲时间用于完善答辩表达和备份，不重新打开测试集调参。

## 每周里程碑

| 周次 | 必须达到的状态 | 未达到时的取舍 |
| --- | --- | --- |
| 第 1 周 | 真实数据可审计、模型可端到端推理 | 停止扩类别，保留较小闭集 |
| 第 2 周 | API、SQLite、推理和历史闭环通过 | 删除非必要设置项，不删测试 |
| 第 3 周 | 桌面端可独立运行并完成 Windows 打包 | 停止视觉美化，优先稳定性 |
| 第 4 周 | 测试、文档、演示和提交包一致 | 不再加功能，只修阻断缺陷 |

## 最终提交检查单

- 可执行程序或明确的一键启动脚本
- 检测器、分类器、ONNX、人物映射、番剧映射和阈值
- SQLite 初始化/迁移与演示数据库
- 需求规格、系统设计、数据库设计、API 说明、测试报告、用户手册和模型卡
- 数据来源、许可、人物人工映射和冻结测试集清单
- 自动化测试输出、真实指标、性能数据和已知限制
- 独立演示截图，不包含训练集样本
